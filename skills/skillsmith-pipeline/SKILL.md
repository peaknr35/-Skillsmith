# Skillsmith pipeline operator

Skillsmith compiles a text PDF into a tested, on-demand skill package — not a paper summary. Every section of the source is accounted for in a coverage ledger; actionable parts become units with trigger conditions, imperative steps, page-cited defaults, negative boundaries, failure modes, and graded evidence (A controlled, B observational, C heuristic). Layout: `E:\Skillsmith\engine` (code, tests, and the contract with its amendments in `build\SPEC-V2.md`), `E:\Skillsmith\runs\<name>` (one workspace per source; a bare name works, e.g. `skillsmith run icm-paper`), `E:\Skillsmith\skills` (finished skills), `E:\Skillsmith\.env` (the API key, found upward from the working folder). The CLI is `skillsmith`; run it from `E:\Skillsmith\engine`.

## Ground rules (follow every time)
1. **Humans own gates and secrets.** Run `skillsmith approve` only after the user says so in words. Never print, ask for, or paste the API key; it lives in a `.env` file the user creates (`ANTHROPIC_API_KEY=`). Exporting into `~/.claude/skills` is also the user's call.
2. **One stage per `skillsmith run` call.** Stop at each gate and show the user what to review. `--stage 0X_name` re-runs one stage; re-running deletes that stage's `APPROVED` and marks every later stage pending.
3. **Fix at the source.** Bad output is fixed by editing `_config/` prompts or a deterministic check, never by hand-editing generated skill text. The one exception is a gate edit: a human decision recorded in `gate-edits.md`.
4. **Label evidence exactly:** fake-LLM tested, real-document tested, live-LLM tested, independently QA'd. Say what a check does not prove: `verify` checks number-to-unit integrity, `audit` checks lexical step-to-page support, neither proves semantic claim fidelity; `eval-run` checks skill-specific markers, while `eval-quality` checks whether a blind judge prefers the answer on generic user-helpfulness criteria.
5. **Abstain or downgrade artifact type honestly.** Scanned PDFs (no text layer) stop at stage 01. At stage 02, every proposal for an `execution_skill` must pass the Triad membership test (`modular`, `late_binding`, `state_transforming`; arXiv 2608.29596). If a source offers trade-offs without a fixed procedure, set `artifact: "decision_guide"`; if it is an empirical study or benchmark with no procedure, set `artifact: "evidence_reference"`; if it changes nothing a practitioner would do (pure survey or position piece), set `actionable: false` and stop. Never synthesize a hollow playbook.

## Setup
- From `E:\Skillsmith\engine`: `pip install -e ".[anthropic]"` (also `[openai]`, `[langchain]`, `[dev]`). `mcp` must stay below 2.
- Create the workspace: `skillsmith init <dir> --source paper.pdf`. The workspace is an ICM folder: `_config/` (rules and prompts), `stages/01_ingest ... 06_eval`.
- LLM stages are 02, 03, 04, 06 and need `--provider anthropic` (or `openai`, or `langchain --model provider:model`). Stages 01 and 05 are deterministic Python.

## Procedure
1. **Stage 01 ingest** (`skillsmith run <ws>`). Check `meta.json`: `page_basis` is `printed` when the printed-page offset was found, else `pdf` (printed pages unknown, citations carry PDF pages only). `source_title` and `source_author` are recorded for attribution. Read `toc.md`: sections come from the PDF outline, else heading patterns. Sections over about 8k tokens are split with page markers preserved. Expect borderless tables to lose column alignment (known limit).
2. **Stage 02 map** then **review gate**. Open `source_map.json` (`map.md` is a rendering). Check:
   - `actionable` and `triad` (`modular`, `late_binding`, `state_transforming`): code rejects any `execution_skill` proposal if the triad is missing or false.
   - `artifact` per proposed skill: `execution_skill` | `decision_guide` | `evidence_reference`.
   - Every section triaged: sections holding decision criteria, comparison tables or scope limits ("when the method loses") are `framework`, not `evidence`; references and front matter are `skip`.
   - A source of 30 PDF pages or fewer maps to exactly one standard skill (code enforces this; splitting a short paper makes sub-skills compete for triggers).
   - Skill descriptions start with `Use when `, are third person outside quoted user phrasings, and include negative exclusions.
   Edit `source_map.json` if needed, then on the user's word: `skillsmith approve <ws> 02_map`.
3. **Stage 03 extract** (one call per non-skipped section; never loads the whole source). Read `coverage.md`: every section is extracted, empty with a stated `no_units_reason`, or skipped by the map (coverage vs compression). Look at pages with no cited unit and at `output/failed/` (rejected attempts show what the checks caught). Code rejects invented numbers, `quote_hint` phrases not verbatim on the cited PDF page, and cites outside the section. Skim `units/*.md` for unit quality: concrete steps, negative boundaries kept, evidence graded (A controlled, B observational, C practitioner heuristic).
4. **Stage 04 consolidate** then **review gate**. Hierarchical: one call per proposed skill over only its sections' units (batched over 12k tokens, then merged). The model returns a JSON merge plan; deterministic code builds merged units from the originals so citations, numbers and boundaries are inherited without loss. `accounting.md` must show every stage-03 unit ID carried into `source_units` or in `excluded` with a reason. Read `conflicts.md` and decide each item with the user against the PDF text, not memory. Record edits in `gate-edits.md`, keep accounting intact, then on the user's word: `skillsmith approve <ws> 04_consolidate`.
5. **Stage 05 write, verify, and audit.** Compiles `SKILL.md`, `playbook.md`, `tool.json`, `system_prompt.md`, `references/evidence.md`, and `references/provenance.json` (source SHA-256, unit lineage, cited pages, evidence grades).
   - `SKILL.md` is at most 500 lines (`full` -> `lean` -> `index`; nothing is deleted). It opens with a **Fit check** (decision units + negative boundaries) and answer-facing rules that prevent over-applying the method on neutral tasks or citing an unmentioned paper at the user. Duplicate steps across units are collapsed in `SKILL.md` to reduce Procedural Exposure Bias (arXiv 2610.26062) while `playbook.md` keeps every unit self-contained.
   - Run `skillsmith verify <ws>`: exit 0 means every number in `SKILL.md`, `playbook.md`, and `system_prompt.md` traces to a page-cited unit.
   - Run `skillsmith audit <ws>`: checks the section coverage ledger, stage-03 -> stage-04 unit accounting, procedural exposure, `quote_hint` presence, and lexical step-to-page overlap per unit (`strong` / `partial` / `weak`). Inspect any `partial` or `weak` unit against `pages.jsonl`.
6. **Stage 06 eval, eval-run, and eval-quality.**
   - `skillsmith run <ws> --provider anthropic` writes `eval.json`, `triggers.md`, and `tasks.md`: >=10 should-fire prompts, >=10 near-miss should-not-fire prompts, and 3-5 tasks. At least 2 tasks must be neutral (zero method cue words, computed by code with a targeted rewrite repair). Tasks include `process_checks` (how the answer proceeds, not just its conclusion; SkillForgeBench arXiv 2610.14918) and can include near-miss tasks (`expect_apply: false`) where a boundary is violated.
   - Run `skillsmith eval-run <ws> --provider anthropic` (add `--with-playbook` to include `playbook.md`): runs the trigger discrimination test with distractors, then the with/without-skill task comparison, reporting individual rubric pass counts, **strict completion** (all items passed at once), and **near-miss over-application**.
   - Run `skillsmith eval-quality <ws> --provider anthropic --judge-model <model>` (use `--eval-file` to compare against a frozen `eval.json` after rebuilding stage 05): repeated with/without-skill answers judged in random order on five generic user-helpfulness criteria (`solves_problem`, `fits_constraints`, `risks_and_limits`, `actionability`, `honesty`) with an exact two-sided sign test and confound tracking (length, visible unit IDs or page cites). Read the saved outputs under `stages/06_eval/runs/` and `stages/06_eval/quality/` yourself.
7. **Export and serve** only when the user asks: `skillsmith export <ws> --dest "$env:USERPROFILE\.claude\skills"`. It refuses to overwrite and needs stages 05 and 06 done. `skillsmith router <dir>` prints a name-and-description prompt for LLMs without skill support; `skillsmith mcp-serve <dir>` serves skills over MCP (`list_skills`, `match_skills` across the library by unit capability witnesses, `get_playbook`, `get_system_prompt`, plus one unit-selecting tool per skill).

## Research foundations & when something fails
- Read `references/failure-modes.md` when a stage, check, or eval fails: it lists every failure mode observed in real runs (including the neutral-task over-application failure found by `eval-quality`) and its fix.
- Read `references/literature-foundations.md` when the user asks about the research behind agent skills, why a check exists, or how to design or evolve a skill library.

## Report format
End each stage with: what ran, what the checks proved, what they did not, what the user must decide, the exact next command. Never call a fake-LLM test run a live validation.
